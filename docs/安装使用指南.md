## 项目简介

**Trail of Bits Skills Marketplace** 是由 Trail of Bits 安全公司提供的 Claude Code 插件市场，为 AI 辅助的安全分析、测试和开发工作流提供专业技能支持。

### 什么是 Claude Code？

Claude Code 是一款 AI 编程助手，通过安装 Trail of Bits Skills，可以让 Claude 具备专业的安全审计、漏洞检测和代码分析能力。

### 为什么要使用这些技能？

- ✅ **专业化**：基于 Trail of Bits 多年安全审计经验
- ✅ **自动化**：自动化执行复杂的安全分析任务
- ✅ **全面覆盖**：支持智能合约、移动应用、后端系统等多个领域
- ✅ **开源免费**：基于 CC-BY-SA-4.0 许可证

## 快速开始

### 步骤 1：添加市场

在 Claude Code 中执行：

```bash
/plugin marketplace add trailofbits/skills
```

### 步骤 2：浏览并安装插件

```bash
/plugin menu
```

在菜单中选择您需要的插件进行安装。

### 步骤 3：使用技能

安装后，直接向 Claude 描述您的需求，例如：

```
"分析这个智能合约的安全漏洞"
"检测这段代码是否存在时序侧信道漏洞"
"为这个 Android APK 扫描 Firebase 安全配置问题"
```

#### 1.2 Entry Point Analyzer（合约入口点分析器）

**插件名称**：`entry-point-analyzer`

**应用场景**

- **审计攻击面分析**：快速识别智能合约的所有外部可调用函数
- **权限分析**：识别哪些函数是公开的，哪些需要特殊权限
- **安全优先级排序**：优先审计公开的、状态变更的函数

##### 支持的语言

| 语言 | 文件扩展名 | 框架支持 |
|------|-----------|---------|
| Solidity | `.sol` | OpenZeppelin, 自定义修饰符 |
| Vyper | `.vy` | 原生模式 |
| Solana | `.rs` | Anchor, Native |
| Move | `.move` | Aptos, Sui |
| TON | `.fc`, `.func`, `.tact` | FunC, Tact |
| CosmWasm | `.rs` | cw-ownable, cw-controllers |

##### 访问级别分类

1. **Public（公开）** — 任何人都可以调用，审计最高优先级
2. **Role-Restricted（角色限制）** — 仅限特定角色（管理员、治理等）
3. **Review Required（需要审查）** — 访问模式不明确，需要手动验证
4. **Contract-Only（仅合约）** — 内部集成点（回调、钩子）

##### 安装方式

```bash
/plugin install trailofbits/skills/plugins/entry-point-analyzer
```

##### 使用示例

```
分析这个合约代码库的入口点
找出 src/core/ 目录中的所有外部函数和访问级别
这个项目中有哪些特权操作？
```

3. **全局系统理解** - 状态/不变量重建、工作流映射、信任边界

#### 2.3 Differential Review（差异化安全审查）

**插件名称**：`differential-review`

**作者**：Omar Inuwa

**应用场景**

- **PR 安全审查**：审查代码变更中的安全漏洞
- **安全回归检测**：检测重新引入的已修复漏洞
- **影响面分析**：计算代码变更的影响范围
- **测试覆盖率缺口**：识别修改代码的测试覆盖缺失

##### 核心功能

- **风险优先分析** - 优先检查认证、加密、价值转移、外部调用
- **Git 历史分析** - 使用 blame 理解代码存在原因并检测回归
- **影响面计算** - 通过统计调用者数量量化影响
- **测试覆盖缺口** - 识别未测试的变更
- **自适应深度** - 根据代码库规模调整分析（小/中/大）

##### 工作流程

1. **预分析** - 使用 `audit-context-building` 构建基线上下文
2. **阶段 0：接收** - 提取变更，评估规模，风险评分文件
3. **阶段 1：变更代码分析** - 分析差异，git blame，检查回归
4. **阶段 2：测试覆盖** - 识别覆盖缺口
5. **阶段 3：影响面** - 计算变更影响
6. **阶段 4：深度上下文** - 五个为什么根因分析
7. **阶段 5：对抗性分析** - 使用攻击者模型挖掘漏洞
8. **阶段 6：报告** - 生成综合 markdown 报告

##### 安装方式

```bash
/plugin install trailofbits/skills/plugins/differential-review
```

##### 使用示例

```
审查这个 PR 的安全影响：git diff main..feature/auth-changes
对比 commit abc123 和 def456 之间的安全变更
```

#### 2.4 Insecure Defaults（不安全默认配置检测）

**插件名称**：`insecure-defaults`

**应用场景**

- **安全审计**：检测生产应用或服务中的不安全默认配置
- **配置审查**：审查部署清单（Docker、Kubernetes、IaC）
- **预生产检查**：部署新服务前的安全检查
- **代码审查**：检查认证、授权或加密代码
- **环境变量处理**：分析机密管理的环境变量处理
- **API 安全审查**：检查 CORS、速率限制、认证
- **第三方集成**：审查硬编码的测试凭证

##### 检测内容

- **硬编码的回退密钥**（JWT 密钥、API 密钥、会话密钥）
- **默认凭证**（admin/admin、root/password）
- **弱加密默认值**（MD5、DES、ECB 模式）
- **宽松的访问控制**（CORS *、默认公开）
- **缺失的安全配置**导致的失败开放行为

##### 关键原则

**失败安全 vs. 失败开放**：
- ✅ 没有正确配置就崩溃的应用是安全的
- ❌ 使用不安全默认值运行的应用是有漏洞的

##### 安装方式

```bash
/plugin install trailofbits/skills/plugins/insecure-defaults
```

##### 使用示例

```
审计这个代码库的不安全默认配置，重点关注环境变量回退和认证配置
检查 config/ 目录中是否存在硬编码的密钥或弱加密配置
```

#### 2.7 Sharp Edges（危险 API 检测）

**插件名称**：`sharp-edges`

**应用场景**

- **API 设计审查**：审查与安全相关的接口
- **配置架构审计**：审计暴露安全选择的配置架构
- **加密库人体工程学评估**：评估加密库的易用性
- **认证/授权 API 评估**：评估认证/授权 API
- **任何开发者做出安全关键决策的代码审查**

##### 核心原则

**成功之坑**：安全使用应该是阻力最小的路径。如果开发者必须仔细阅读文档或记住特殊规则以避免漏洞，那么 API 就失败了。

##### 三种对手分析

1. **恶意开发者（The Scoundrel）**：恶意开发者或攻击者能否通过配置禁用安全性？
2. **懒惰开发者（The Lazy Developer）**：复制粘贴第一个示例会导致不安全的代码吗？
3. **困惑开发者（The Confused Developer）**：参数能否在没有类型错误的情况下交换？

##### 危险边缘类别

| 类别 | 示例 |
|------|------|
| **算法选择** | JWT `alg: none` 攻击；PHP `hash("crc32", $password)` |
| **危险默认值** | `session_timeout: 0` 表示无限；接受空密码 |
| **原始 vs. 语义 API** | `encrypt(msg, bytes, bytes)` 其中 key/nonce 可以交换 |
| **配置悬崖** | `verify_ssl: false` 禁用所有证书验证 |
| **静默失败** | 验证返回 `False` 而不是抛出异常；忽略返回值 |
| **字符串类型的安全** | 权限作为逗号分隔字符串；从连接构建 SQL |

##### 安装方式

```bash
/plugin install trailofbits/skills/plugins/sharp-edges
```

##### 使用示例

```
审查这个认证 API 的设计，查找危险边缘
分析 config.yaml 中的安全配置选项
```

#### 3.1 Constant-Time Analysis（常量时间分析）

**插件名称**：`constant-time-analysis`

**应用场景**

- **加密代码审计**：检测编译后的加密代码中的时序侧信道漏洞
- **多编译器测试**：分析来自多个编译器和架构的汇编输出
- **CI/CD 集成**：在持续集成中自动检测时序漏洞
- **脚本语言支持**：分析 PHP、JavaScript/TypeScript、Python、Ruby 的字节码

##### 核心功能

检测可能导致时序侧信道的指令：

- **硬件除法**（`DIV`、`IDIV`）：执行时间取决于操作数值
- **浮点运算**（`FDIV`、`FSQRT`）：基于输入的可变延迟
- **条件分支**：不同执行路径具有不同的时序

##### 支持的语言和架构

**语言**: C, C++, Go, Rust, PHP, JavaScript, TypeScript, Python, Ruby

**架构**: x86_64, ARM64, ARM, RISC-V, PowerPC, s390x, i386

**编译器**: GCC, Clang, Go compiler, Rustc

##### 检测到的漏洞

**错误级别（必须修复）**

| 类别 | x86_64 | ARM64 | RISC-V |
|------|--------|-------|--------|
| 整数除法 | DIV, IDIV | UDIV, SDIV | DIV, DIVU, REM |
| 浮点除法 | DIVSS, DIVSD | FDIV | FDIV.S, FDIV.D |
| 平方根 | SQRTSS, SQRTSD | FSQRT | FSQRT.S, FSQRT.D |

**警告级别（需要审查）**

条件分支可能泄漏时序（如果条件依赖于秘密数据）：
- x86: JE, JNE, JZ, JNZ, JA, JB, JG, JL 等
- ARM: BEQ, BNE, CBZ, CBNZ, TBZ, TBNZ
- RISC-V: BEQ, BNE, BLT, BGE

##### 脚本语言支持详情

**PHP 分析**
- 使用 VLD 扩展或 opcache 调试输出
- 检测：`ZEND_DIV`、`ZEND_MOD`、缓存时序、表查找等

**JavaScript/TypeScript 分析**
- 使用 Node.js `--print-bytecode` 的 V8 字节码
- TypeScript 文件自动转译
- 检测：`Div`、`Mod` 字节码、数组访问、位移位等

**Python 分析**
- 使用内置的 `dis` 模块分析 CPython 字节码
- 检测：`BINARY_OP`、`BINARY_SUBSCR`、位移位等

**Ruby 分析**
- 使用 YARV 字节码 via `ruby --dump=insns`
- 检测：`opt_div`、`opt_mod`、数组访问等

##### 安装方式

```bash

# 或通过插件安装

```

# 包括条件分支警告
ct-analyzer --warnings crypto.c

# 分析特定函数

# CI 的 JSON 输出

# 分析其他语言

##### 修复违规示例

**用 Barrett 约简替换除法**

```c
// 有漏洞
int32_t q = a / divisor;

// 安全：Barrett 约简
uint32_t q = (uint32_t)(((uint64_t)a * mu) >> 32);
```

**用常量时间选择替换分支**

```c
// 有漏洞
if (secret) {
    result = a;
} else {
    result = b;
}

// 安全：常量时间选择
uint32_t mask = -(uint32_t)(secret != 0);
result = (a & mask) | (b & ~mask);
```

##### 局限性

1. **编译器输出分析**：分析编译器生成的内容，而非运行时行为
2. **无数据流分析**：标记所有危险指令，无论它们是否操作秘密数据（预期会有误报）
3. **误报验证**：对于每个标记的违规，验证操作数是否为秘密
4. **编译器变化**：不同的编译器/版本可能产生不同的汇编

#### 3.3 Spec-to-Code Compliance（规范到代码合规性检查）

**插件名称**：`spec-to-code-compliance`

**作者**：Omar Inuwa

**应用场景**

- **代码与规范一致性**：验证代码是否完全按照文档规范实现
- **差距查找**：查找预期行为和实际实现之间的差距
- **智能合约审计**：根据白皮书或设计文档审计智能合约
- **未记录行为**：识别未记录的代码行为或未实现的规范声明

##### 核心功能

执行基于证据的规范与代码之间的确定性对齐：

- **文档发现** - 查找所有规范来源（白皮书、README、设计说明）
- **规范意图提取** - 将所有预期行为规范化为结构化格式
- **代码行为分析** - 逐行对实际实现进行语义分析
- **对齐比较** - 将规范项目映射到带有匹配类型和置信度分数的代码
- **偏差分类** - 按严重性（Critical/High/Medium/Low）对不一致进行分类

##### 关键原则

**零推测。**每个声明都必须有以下支持：
- 来自文档的确切引用（部分/标题）
- 特定代码引用（文件 + 行号）
- 所有映射的置信度分数（0-1）

##### 匹配类型

- `full_match` - 代码完全实现规范
- `partial_match` - 不完整的实现
- `mismatch` - 规范说 X，代码做 Y
- `missing_in_code` - 规范声明未实现
- `code_stronger_than_spec` - 代码添加行为
- `code_weaker_than_spec` - 代码缺少要求

##### 7 个阶段

1. **文档发现** - 识别所有规范来源
2. **格式规范化** - 创建清晰的规范语料库
3. **规范意图 IR** - 提取所有预期行为
4. **代码行为 IR** - 逐行代码分析
5. **对齐 IR** - 将规范与代码进行比较
6. **偏差分类** - 对不一致进行分类
7. **最终报告** - 生成审计级合规性报告

##### 安装方式

```bash
/plugin install trailofbits/skills/plugins/spec-to-code-compliance
```

##### 使用示例

```

检查代码实现与 DESIGN.md 中的设计文档之间的差异
```

|------|------|------|
| **uv** | pip, virtualenv, pip-tools, pipx, pyenv | 包/依赖管理 |
| **ruff** | flake8, black, isort, pyupgrade | Linting 和格式化 |
| **ty** | mypy, pyright | 类型检查 |
| **pytest** | - | 测试与覆盖率强制 |
| **prek** | pre-commit | Pre-commit hooks |

##### 安全工具

- **shellcheck** - Shell 脚本 linting
- **detect-secrets** - 提交中的秘密检测
- **actionlint** - GitHub Actions 语法验证
- **zizmor** - GitHub Actions 安全审计
- **pip-audit** - 依赖漏洞扫描
- **Dependabot** - 自动化依赖更新与供应链保护

##### 标准

- **pyproject.toml** - 带有依赖组的单一配置文件（PEP 735）
- **PEP 723** - 单文件脚本的内联脚本元数据
- **src/ 布局** - 标准包结构
- **Python 3.11+** - 最低版本要求

##### Hook: 传统命令拦截

此插件包含一个 `PreToolUse` hook，可拦截传统的 Python/pip 命令并建议 uv 替代方案：

| 传统命令 | 建议替代 |
|---------|---------|
| `python` | `uv run python` |
| `python script.py` | `uv run script.py` |
| `pip install pkg` | `uv add pkg` 或 `uv run --with pkg` |
| `pip uninstall pkg` | `uv remove pkg` |
| `pip freeze` | `uv export` |
| `python -m pip` | `uv add`/`uv remove` |
| `uv pip` | `uv add`/`uv remove`/`uv sync` |

##### 安装方式

```bash
/plugin install trailofbits/skills/plugins/modern-python
```

##### 使用示例

```
创建一个新的现代 Python 项目
将这个项目迁移到使用 uv 和 ruff
为这个项目设置 pre-commit hooks 和安全扫描
```

### 8. 团队管理

#### 8.1 Culture Index（文化指数解读）

**插件名称**：`culture-index`

**作者**：Dan Guido

**应用场景**

- **个人档案解读**：解读个人的文化指数档案
- **团队组成分析**：分析团队组成的 gas/brake/glue 平衡
- **倦怠检测**：通过比较 Survey vs Job 特征检测倦怠信号
- **档案兼容性**：比较多个档案的兼容性
- **激励建议**：获取特定特征类型的激励建议

##### 核心功能

- **相对解读** - 始终使用与箭头的距离，从不使用绝对值
- **Survey vs Job 分析** - 识别行为修改和能量消耗
- **模式识别** - 将档案映射到 19 个原型
- **团队分析** - 评估 gas/brake/glue 平衡和差距
- **倦怠检测** - 计算能量利用率并标记风险

##### 特征颜色

| 特征 | 颜色 | 测量 |
|------|-----|------|
| A | 酒红色 | 自主性、主动性 |
| B | 黄色 | 社交能力 |
| C | 蓝色 | 节奏/耐心 |
| D | 绿色 | 一致性、细节 |
| L | 紫色 | 逻辑 |
| I | 青色 | 创造力 |

##### 能量利用率

```
利用率 = (Job EU / Survey EU) x 100

70-130% = 健康
>130% = 压力（倦怠风险）
<70% = 沮丧（离职风险）
```

##### Gas/Brake/Glue 框架

| 角色 | 特征 | 功能 |
|------|-----|------|
| Gas | 高 A | 增长、冒险 |
| Brake | 高 D | 质量控制 |
| Glue | 高 B | 关系、士气 |

##### 输入格式

- **JSON** - 从 culture-index 工具提取的档案（推荐）
- **PDF** - 使用 Claude 的视觉直接分析 PDF

##### 安装方式

```bash
/plugin install trailofbits/skills/plugins/culture-index
```

##### 使用示例

```
解读这个文化指数档案 PDF
分析我们团队的组成和平衡
比较这两个候选人的档案兼容性
这个人的 Survey 和 Job 结果有什么不同？
```

1. `/audit-context-building` - 建立基线上下文
2. `/differential-review` - 审查代码变更
3. `/variant-analysis` - 查找类似漏洞
4. `/fix-review` - 验证修复

## 常见问题

### Q1: 如何知道哪个技能适合我的任务？

查看本文档的"应用场景"部分，或直接向 Claude 描述您的需求，让它推荐合适的技能。

### Q2: 技能需要额外安装工具吗？

一些技能需要外部工具：
- `burpsuite-project-parser` 需要 Burp Suite Professional
- `static-analysis` 需要 CodeQL 和/或 Semgrep
- `constant-time-analysis` 需要编译器（gcc/clang/rustc/go）
- `firebase-apk-scanner` 需要 apktool、curl、jq

大多数技能会在需要时告诉您如何安装这些工具。

### Q3: 技能可以用于商业项目吗？

是的，所有技能基于 CC-BY-SA-4.0 许可证，可以用于商业项目。但请务必遵守各个工具的许可证（如 Semgrep、CodeQL 等）。

### Q4: 如何更新技能？

```bash
/plugin update trailofbits/skills
```

### Q5: 技能支持哪些编程语言？

不同技能支持不同语言：
- **智能合约**: Solidity, Vyper, Solana (Rust), Move, TON, CosmWasm
- **通用**: C/C++, Python, JavaScript/TypeScript, Go, Rust, Java, Ruby, PHP
- **查看每个技能的文档以了解具体支持的语言**

### Q6: 发现 bug 后如何报告？

如果您使用这些技能发现了漏洞，欢迎[提交到 Trophy Case](https://github.com/trailofbits/skills/issues/new?template=trophy-case.yml)！

报告时可以提及：
> Found using [Trail of Bits Skills](https://github.com/trailofbits/skills)

```bash

/plugins marketplace add ./skills
```
