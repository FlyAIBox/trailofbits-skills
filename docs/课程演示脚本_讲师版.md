### 演示步骤(13分钟)

#### Step 1: 引入Fail-Safe概念(3分钟)

**讲师说**:
```
在讲这个场景之前,我先问大家一个问题:

如果你的服务启动时,发现数据库密码没配置,
你希望它:
A. 使用一个默认密码(admin/admin),然后正常启动
B. 直接崩溃,拒绝启动

举手表决一下?
```

**互动**: 让学员举手选择

**讲师揭晓答案**:
```
正确答案是B!

这就是"Fail-Safe"(失败安全)原则:
- ❌ Fail-Open: 配置错误→用不安全默认值→服务运行→安全漏洞
- ✅ Fail-Safe: 配置错误→拒绝启动→强制修复→安全运行

今天要讲的insecure-defaults,
就是专门检测Fail-Open问题的。
```

**展示对比代码**:
```python
# ❌ Fail-Open (危险)
SECRET_KEY = os.getenv('SECRET_KEY', 'default-secret-123')

# ✅ Fail-Safe (安全)
SECRET_KEY = os.environ['SECRET_KEY']  # 没配置就崩溃
```

```
最后一个重要话题: 安全。

用AI工具很爽,但在生产环境使用需要谨慎。
我给大家总结了6大安全原则。
```

**原则1: 人工审核门控**

```
❌ 错误: AI生成代码 → 自动提交 → 自动部署
✅ 正确: AI生成代码 → 人工Review → 批准 → 部署

记住: AI是建议者,人类是决策者!
```

**原则2: 敏感数据隔离**

```
❌ 危险: 把生产数据库密码发给AI
✅ 安全: 先脱敏,用***替换敏感数据

示例:
  原始: DATABASE_URL='postgresql://admin:Pass123@10.0.1.50/prod'
  脱敏: DATABASE_URL='postgresql://***:***@***/***'
```

**原则3: 最小权限**

```
给AI的权限:
  ✅ contents: read        (可以读代码)
  ✅ pull-requests: write  (可以创建PR)
  ❌ secrets: read         (绝对不能!)
  ❌ deployments: write    (绝对不能!)
```

**原则4: 审计日志**

```python
# 所有AI操作必须记录
log_ai_action(
    action="differential_review",
    user="alice@company.com",
    input_hash=hash(input),
    timestamp=now()
)
```

**原则5: 渐进式部署**

```
阶段1: 个人实验(1周)
阶段2: 团队试点(2-4周)
阶段3: 部门推广(1-2月)
阶段4: 全公司推广(3-6月)

不要一上来就全公司推广!
```

**原则6: 故障降级**

```python
try:
    result = ai_review(pr)
except AIServiceDown:
    # AI挂了,降级到人工审查
    notify_human_reviewers()
```

### 生产环境检查清单

**PPT: 简化版清单**

```
上生产前,确保:
  □ ✅ AI输出都经过人工审核
  □ ✅ 敏感数据已脱敏
  □ ✅ 配置了审计日志
  □ ✅ 有故障降级方案
  □ ✅ 团队成员已培训
```

**讲师强调**:
```
安全不是可选项,是必选项!

记住这些原则,可以避免90%的坑。
```
