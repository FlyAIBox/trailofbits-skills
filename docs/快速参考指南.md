## 💡 使用示例

### 场景1: 创建新项目

```
创建一个新的现代Python项目,要求:
- 项目名称: my-service
- 框架: FastAPI
- 包含用户认证模块
- 包含数据库ORM
```

**AI会做**: 创建项目结构、配置工具、生成代码框架  
**你需要做**: 审核结果、开始写业务逻辑

---

### 场景2: 审查PR

```
使用differential-review审查这个PR的安全影响
提交: git diff main..feature/my-feature
```

**AI会做**: 分析变更、检测安全问题、计算影响面、生成报告  
**你需要做**: 基于报告做决策(批准/拒绝/要求修改)

---

### 场景3: 安全扫描

```
使用insecure-defaults审计这个服务的配置安全性,
重点关注环境变量回退和认证配置
```

**AI会做**: 扫描配置、识别Fail-Open问题、生成修复建议  
**你需要做**: 按优先级修复问题、验证修复效果

用这个5问法:

| 问题 | 是/否 |
|------|-------|
| 1. 重复性高?(每天/每周都做) | |

| 3. 知识密集?(需要查很多文档) | |
| 4. 容易出错?(人工检查会遗漏) | |

**5个都是"是"** → 非常适合Skill化!

## 🔐 安全6原则

```
✅ 1. 人工审核门控 - AI建议,人类决策
✅ 2. 敏感数据隔离 - 先脱敏再发给AI
✅ 3. 最小权限原则 - AI不能访问secrets
✅ 4. 审计日志 - 记录所有AI操作
✅ 5. 渐进式部署 - 从小范围试点开始
✅ 6. 故障降级方案 - AI挂了也能工作
```

---

## ⚡ Fail-Safe原则

```
❌ Fail-Open (危险):
   SECRET_KEY = os.getenv('SECRET_KEY', 'default')
   配置错误→使用不安全默认值→安全漏洞

✅ Fail-Safe (安全):
   SECRET_KEY = os.environ['SECRET_KEY']
   配置错误→崩溃→强制修复→安全运行

记住: 崩溃比不安全运行好!
```
