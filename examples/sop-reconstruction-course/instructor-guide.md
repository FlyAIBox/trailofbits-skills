## 课程大纲与时间分配

### Part 1: 传统SOP的问题与挑战 (10分钟)

**目标**：让学员认同"需要改变"

**关键点**：
- 用数据说话（2-3天 vs 1天）
- 真实案例引起共鸣
- 强调痛点的普遍性

**讲解要点**：
1. **开场**（2分钟）
   - 自我介绍
   - 课程目标介绍
   - 互动：举手调查"谁遇到过需求反复返工？"

2. **传统SOP介绍**（3分钟）
   - 7个环节快速过一遍
   - 重点讲3个关键环节（需求、编码、审查）
   - 使用流程图可视化

3. **痛点分析**（5分钟）
   - **痛点1：需求澄清**
     - 讲故事：某次项目因密码存储方式理解错误返工
     - 数据：平均2-3天沟通
   
   - **痛点2：编码实现**
     - 演示：5个开发者5种环境配置方式
     - 问题：代码风格不一致的截图
   
   - **痛点3：代码审查**
     - 案例：21个问题只发现3个
     - 强调：安全问题遗漏的后果

**互动建议**：
- "大家在需求阶段平均花多长时间？"
- "举手：谁的项目因需求理解偏差返工过？"

---

### Part 2: 改造后的效果演示 (15分钟)

**目标**：让学员看到"改变的价值"

**关键点**：
- 先展示结果（吸引注意力）
- 再展示过程（建立信任）
- 对比强烈（视觉冲击）

**讲解要点**：

1. **效果总览**（2分钟）
   - 展示对比表格
   - 强调关键数据：3天 → 1天
   - 引出："是怎么做到的？"

2. **实战演示**（10分钟）
   - **演示1：需求澄清**（3分钟）
     ```
     传统：开发者猜测 → 后续返工
     Skill：AI主动提问 → 一次到位
     ```
     - 实时演示或播放录屏
     - 强调：多选题格式、带默认值
   
   - **演示2：编码实现**（3分钟）
     ```
     传统：手动配置混乱
     Skill：自动标准化
     ```
     - 展示生成的项目结构
     - 对比pyproject.toml vs requirements.txt
     - 展示Hook拦截（`pip install` → `uv add`）
   
   - **演示3：代码审查**（4分钟）
     ```
     传统：看起来没问题（实际21个bug）
     Skill：发现4个关键问题
     ```
     - 展示AI分析报告
     - 逐一讲解4个问题
     - 强调：人类最终决策

3. **关键改进总结**（3分钟）
   - 被动 → 主动
   - 手动 → 自动
   - 浅层 → 深度

**演示技巧**：
- **如果实时演示失败**：立即切换到录屏视频
- **保持节奏**：每个演示不超过3分钟
- **互动**："大家觉得哪个改进最有价值？"

---

### Part 3: 为何选择Claude Skill (10分钟)

**目标**：让学员理解"为什么是Skill"

**关键点**：
- 技术方案横向对比（建立判断标准）
- Skill的独特优势（差异化价值）
- 选型决策树（可复用方法论）

**讲解要点**：

1. **四种方案对比**（4分钟）
   - 纯Prompt、RAG、Agent、Skill
   - 每种方案1分钟：优势 + 劣势 + 适用场景
   - 强调：不是Skill最好，而是最适合SOP改造

2. **Skill的4大优势**（4分钟）
   - **原子化封装**
     - 类比：乐高积木 vs 散装零件
     - 示例：ask-questions = 提问能力 + 触发条件 + 执行规则
   
   - **可组合性**
     - 类比：配方 vs 单一食材
     - 示例：3个Skills组合成完整工作流
   
   - **控制点清晰**
     - 图示：Human决策 → Skill执行 → Human验收
     - 强调：人类始终掌控
   
   - **安全保障**
     - Hook拦截危险操作
     - 暂停点等待确认
     - 只读模式防止自动修复

3. **选型决策树**（2分钟）
   - 展示决策流程图
   - 强调：根据场景选择，不盲从
   - 对于1-2年开发者，Skill是最佳起点

**讲解技巧**：
- 使用类比帮助理解（乐高、配方、质检员）
- 图示多于文字（决策树、架构图）
- 强调"可控"（消除AI自动化的恐惧）

### Part 4: Skill改造实战拆解 (20分钟)

**目标**：让学员学会"如何使用"

**关键点**：
- 安装配置（降低门槛）
- 三个Skill详解（建立深度理解）
- 编排方法（可复用套路）

**讲解要点**：

1. **安装配置**（3分钟）
   - 现场演示或播放视频
   - 3条命令：添加市场 → 安装Skill → 验证
   - 强调：非常简单，5分钟搞定

2. **Skill 1详解**（5分钟）
   - **ask-questions-if-underspecified**
   - 功能定位：需求澄清的质量门
   - 工作流程：5步流程图
   - 实战示例：展示真实提问格式
   - 人机分工：Human决策，AI识别决策点
   - **互动**："如果是你，会选哪个选项？"

3. **Skill 2详解**（5分钟）
   - **modern-python**
   - 功能定位：工具链标准化
   - 核心工具：uv, ruff, ty, pytest
   - Hook机制：拦截演示（现场或视频）
   - 生成结构：展示项目树
   - **互动**："大家现在用什么依赖管理工具？"

4. **Skill 3详解**（5分钟）
   - **audit-context-building**
   - 功能定位：深度理解引擎
   - 核心方法：First Principles, 5 Whys, 5 Hows
   - 三阶段：定向 → 细粒度 → 全局
   - 对比示例：浅层 vs 深度分析
   - 强调：只发现问题，不自动修复

5. **编排方法**（2分钟）
   - 流程图：需求 → 开发 → 审查
   - 人机分工矩阵
   - 强调：Skill是工具，人是指挥官

**讲解技巧**：
- 每个Skill都有"实战示例"
- 强调"人机分工"（每个Skill讲一次）
- 使用流程图可视化

## 常见问题解答

### Q1: "如果AI提问错了怎么办？"
**A**: 
- 这是好问题，说明你在思考边界
- ask-questions会暂停等待你确认
- 如果问题不合适，你可以直接告诉AI："这个问题不适用，应该问XX"
- AI会调整提问策略

### Q2: "modern-python拦截旧命令会不会太严格？"
**A**:
- Hook是可配置的，你可以临时禁用
- 目的是帮助养成好习惯，不是限制你
- 如果确实需要用旧命令，告诉AI原因，它会放行

### Q3: "audit-context分析很慢怎么办？"
**A**:
- 深度分析确实需要时间，这是正常的
- 可以先针对关键模块分析，而不是全量
- 平衡：深度 vs 速度，根据项目重要性选择

### Q4: "我们公司用GitLab CI，Skill支持吗？"
**A**:
- modern-python生成的是标准Python工具，与CI无关
- 你可以在GitLab CI中调用uv、ruff等工具
- Skill是本地开发流程，CI是后续集成

### Q5: "免费用户能用这些Skills吗？"
**A**:
- 需要Claude Code才能用Skill机制
- Claude Code目前的价格和限制请查看官网
- 演示中的代码和工具（uv, ruff等）都是开源免费的

### Q6: "能自己写Skill吗？"
**A**:
- 可以！查看仓库中的 CLAUDE.md
- Skills本质是结构化的Prompt + 配置
- 建议先用现有Skill熟悉机制，再尝试自己写

### Q7: "Skill会取代人类吗？"
**A**:
- 不会，Skill增强人类，不是替代
- 关键决策始终由人类做
- AI做重复性、知识密集型工作，人类专注创造性、判断性工作

## 授课技巧总结

### 1. 节奏控制
- **前10分钟**：快速建立问题意识
- **中间30分钟**：深度讲解，穿插演示
- **最后5分钟**：总结升华，激发行动

### 2. 互动设计
- 每10分钟至少1次互动
- 使用举手、投票、提问等方式
- 关注学员反应，调整节奏

### 3. 故障应对
- **网络断开**：切换录屏视频
- **Claude崩溃**：使用截图和代码片段
- **时间不够**：压缩Part 3，保证Part 4完整

### 4. 重点强调
- **重复3次**：人机协作、可控性、标准化
- **视觉化**：多用图表，少用文字
- **具体化**：多举例子，少讲概念

### 5. 收尾要点
- 总结5个关键要点
- 提供学习资源
- 留下联系方式
- 鼓励立即实践
