## 课程设计思路

### 这门课是讲给谁的？

本课程主要适合**1～2年经验的程序员**，具体包括：

**基础要求**：
- ✅ 掌握基本编程能力（Python、JavaScript等）
- ✅ 了解基础的大模型应用（至少会写提示词）
- ✅ 可能看过一些轻量级AI学习资料（如RAG、Prompt Engineering）
- ⚠️ AI落地经验尚浅或没有实际项目经验

**适用人群**：
- **后端开发工程师**：希望用AI提升Python API开发效率
- **全栈开发者**：想要了解如何在实际SOP中应用AI工具
- **技术Lead**：需要为团队设计AI辅助的工作流程
- **DevOps工程师**：关注如何标准化和自动化开发流程

**不适合人群**：
- ❌ 完全没有编程基础的初学者
- ❌ 需要深入学习AI算法原理的研究人员
- ❌ 只想了解大模型理论的人

### 课程开设背景

**行业痛点观察**：

在与众多初中级开发者的交流中，我们发现了一个普遍现象：**大家都知道AI很火，也尝试过用ChatGPT或Claude写代码，但往往只是"临时抱佛脚"式的使用，并没有真正把AI融入日常工作流程**。

**典型困境**：

1. **需求澄清阶段**
   - 问题：接到需求后，总是理解有偏差，要反复和产品确认
   - 现状：知道可以让AI帮忙分析需求，但不知道如何让AI"问对问题"
   - 结果：仍然需要2-3天的多轮沟通，AI没帮上太大忙

2. **编码实现阶段**
   - 问题：项目的工具链配置混乱（pip、virtualenv、black、flake8...）
   - 现状：让AI生成代码，但代码质量参差不齐，工具使用过时
   - 结果：花半天搭环境，代码风格不统一，维护困难

3. **代码审查阶段**
   - 问题：Review时只能做浅层检查，安全问题容易遗漏
   - 现状：不知道如何让AI深入理解代码上下文
   - 结果：70%的安全问题在Review阶段被遗漏，上线后才暴露

**核心矛盾**：
> AI的能力在提升，但大部分开发者还在用"一次性提示词"的方式使用AI，**缺乏系统的、可复用的、可控的AI应用方法**。

**为什么选择Claude Skill作为解决方案？**

经过对多种AI辅助方案的评估（纯Prompt、RAG知识库、Agent框架），我们发现：
- **纯Prompt**：灵活但不可复用，质量不稳定
- **RAG知识库**：适合知识查询，但无法控制执行流程
- **Agent框架**：功能强大但学习曲线陡峭，对初中级开发者不友好

而**Claude Skill**则提供了一个完美的中间方案：
- ✅ **即插即用**：安装后立即生效，无需复杂配置
- ✅ **可控可测**：每个Skill行为可预测，人机分工明确
- ✅ **标准化**：将最佳实践固化为可复用的能力单元
- ✅ **低门槛**：1-2年经验的开发者即可掌握

**课程的独特价值**：

本课程不是教你"如何写Prompt"，而是教你**如何用Skill重构SOP**，让AI真正融入你的日常工作流程。更重要的是，这套方法论可以**迁移到其他类似场景**（前端开发、智能合约审计、遗留系统重构等）。

### 第一部分：传统SOP的问题与挑战（10分钟）

**学习目标**：
- 理解Python API开发的典型流程
- 识别每个环节的现实痛点
- 发现AI介入的机会点

**内容大纲**：

#### 1.1 传统Python API开发SOP（3分钟）
- 典型的7环节流程：需求接收 → 需求澄清 → 技术方案 → 编码 → Review → 测试 → 部署
- 各环节的详细工序和时间消耗
- 行业平均数据：一个简单API从需求到上线需要3天

#### 1.2 现实痛点分析（5分钟）
- **痛点1：需求澄清**
  - 理解偏差，反复确认（耗时2-3天）
  - 遗漏关键约束条件（返工成本高）
  - 多轮邮件/会议沟通（效率低）

- **痛点2：编码实现**
  - 工具链配置繁琐（pip、virtualenv、black...）
  - 代码风格不统一（人工难以保证）
  - 缺乏现代化工具（如uv、ruff）

- **痛点3：代码审查**
  - 缺乏上下文理解（只看局部代码）
  - 浅层检查为主（格式、命名）
  - 安全问题易遗漏（70%遗漏率）

#### 1.3 AI介入的机会点（2分钟）
- 需求澄清 → 需要**主动提问能力**
- 编码实现 → 需要**标准化工具链**
- 代码审查 → 需要**深度理解能力**
- 引出：这正是我们选择的3个Skill的用武之地

**关键要点**：
- 让学员产生共鸣："原来不是我一个人遇到这些问题"
- 建立改造动机："这些痛点是可以通过Skill解决的"

**演示1：需求澄清阶段**（3分钟）
```
传统方式：
- 开发："JWT是用HS256还是RS256？"

- 开发："令牌过期时间多久？"
- 再等待（半天）
- ... 多轮往返
```

```
Skill驱动（modern-python）：
```

**演示3：代码审查阶段**（3分钟）

```
Skill驱动（audit-context-building）：
- 三阶段深度分析（定向 → 细粒度 → 全局）
- 发现4个潜在问题（异常处理、算法攻击、密钥安全等）

```

```
ask-questions + modern-python + audit-context 
= Python API开发SOP
```

**优势3：人机协作控制点清晰**
```
Human: 战略决策、质量把关
   ↓

   ↓
AI: 执行标准化操作

Human: 验收确认
```

**优势4：生产级安全保障**
- Hook机制拦截危险操作
- 版本管理、可回滚
- 行为可预测、可测试

#### 4.2 三个核心Skill详解（12分钟）

##### Skill 1: ask-questions-if-underspecified（4分钟）

**功能定位**：需求澄清阶段的"质量门"

**触发时机**：
- 需求描述模糊
- 存在多种理解方式
- 缺少成功标准

**工作原理**：
```
输入：模糊需求
  ↓
分析：识别歧义点、缺失信息
  ↓
提问：生成1-5个关键问题（多选题格式）
  ↓
暂停：等待用户回答（除非用户明确跳过）
  ↓
输出：确认后的明确需求
```

**实战示例**：
```
用户输入："开发一个用户认证API"

AI响应（启用Skill）：
在开始实现之前，我需要确认以下关键问题：

1. 认证方式？
   A. JWT令牌 (默认)
   B. Session
   C. OAuth2

2. 令牌存储？
   A. Redis (默认)
   B. 内存
   C. 数据库

3. 加密算法？
   A. HS256 (默认)
   B. RS256

4. 令牌过期时间？
   A. 1小时 (默认)
   B. 24小时
   C. 自定义：______

5. 是否需要刷新令牌？
   A. 是 (默认)
   B. 否

请确认以上选项，我将据此实现。
```

**人机协作控制点**：
- **Human**：做业务决策（选择认证方式）
- **AI**：识别决策点并结构化提问
- **Human**：最终确认（避免AI猜测）

**设计精妙之处**：
- 多选题格式降低人类负担
- 提供默认值（方便快速确认）
- 强制暂停等待（不会擅自开工）

##### Skill 2: modern-python（4分钟）

**功能定位**：编码阶段的"工具链标准化"

**核心价值**：
1. 自动配置现代化工具链
2. 拦截过时命令（Hook机制）
3. 强制最佳实践

**工具栈**：
```
uv        → 依赖管理（替代pip/virtualenv）
ruff      → 代码格式化和Lint（替代black/flake8）
ty        → 类型检查（替代mypy）
pytest    → 测试框架
pre-commit→ Pre-commit钩子
pip-audit → 安全扫描
```

**Hook机制演示**：
```python
# 如果你尝试运行：
pip install requests

# Skill会拦截并提示：
❌ 建议使用现代工具：
   uv add requests

# 如果你运行：
python script.py

# Skill会拦截并提示：
❌ 建议使用：
   uv run script.py
```

**自动生成的项目结构**：
```
my-api/
├── pyproject.toml        # 统一配置文件
├── src/
│   └── my_api/
│       ├── __init__.py
│       ├── main.py
│       └── auth.py
├── tests/
│   └── test_auth.py
├── .pre-commit-config.yaml
└── README.md
```

**pyproject.toml示例**：
```toml
[project]
name = "my-api"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = [
    "fastapi>=0.100.0",
    "pyjwt>=2.8.0",
]

[tool.ruff]
line-length = 100
select = ["E", "F", "I", "N", "W"]
```

**人机协作控制点**：
- **Human**：决定使用哪些库（fastapi vs flask）
- **AI**：自动配置工具链，生成标准化项目
- **Human**：Review生成的代码结构

**为什么选择uv而不是pip？**
- 速度快10-100倍
- 统一配置（不需要requirements.txt + setup.py + ...）
- 原生支持PEP 735等现代标准

##### Skill 3: audit-context-building（4分钟）

**功能定位**：代码审查阶段的"深度理解引擎"

**核心思想**：
> 在漏洞扫描前，先建立**完整的系统认知**

**分析方法**：
1. **First Principles**（第一性原理）：不依赖假设，从代码本身推导
2. **5 Whys**（五个为什么）：深挖每行代码的目的
3. **5 Hows**（五个如何）：追踪数据流和控制流

**三阶段流程**：
```
Phase 1: 初始定向（Initial Orientation）
- 模块结构
- 入口点
- 参与角色
- 存储机制

Phase 2: 超细粒度分析（Ultra-Granular Analysis）
- 逐行语义分析
- 跨函数流追踪
- 不变量识别

Phase 3: 全局理解（Global Understanding）
- 状态重建
- 工作流映射
- 信任边界
```

**实战示例**：

对于以下代码：
```python
def verify_token(token: str) -> dict:
    payload = jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
    return payload
```

**传统Review**：
- ✅ 使用JWT库
- ✅ 指定算法
- → 看起来没问题

**Skill驱动的深度分析**：
```
Phase 1: 定向
- 入口点：verify_token
- 输入：token (str)
- 输出：payload (dict)
- 依赖：jwt库, SECRET_KEY

Phase 2: 细粒度分析
Line 2: jwt.decode(token, SECRET_KEY, algorithms=["HS256"])
  - Why: 为什么只用HS256？是否需要支持RS256？
  - How: token如果为None会怎样？
  - How: SECRET_KEY从哪里来？是否安全？
  - How: 解码失败抛出什么异常？
  - How: 调用方是否处理了异常？

Phase 3: 全局理解
- 潜在问题1: 未处理jwt.DecodeError异常
- 潜在问题2: 未验证payload内容（exp, iat）
- 潜在问题3: SECRET_KEY可能硬编码
- 潜在问题4: 未验证算法切换攻击（alg=none）
```

**反幻觉规则**（重要！）：
- ❌ 不假设代码逻辑（"应该会处理异常"）
- ✅ 只基于实际代码推导（"未见异常处理"）
- ❌ 不改变证据适配假设
- ✅ 发现矛盾时更新理解

**人机协作控制点**：
- **AI**：执行逐行深度分析（耗时但全面）
- **Human**：判断哪些问题是真正的风险
- **Human**：决定是否需要修复

**为什么AI只报告问题，不判断严重性？**
- 严重性判断依赖业务上下文
- AI可能不了解实际威胁模型
- 保持人类的最终决策权

## 课程总结：5个关键要点

### 1. 传统SOP的三大痛点
- ❌ 需求澄清：被动等待，多轮返工
- ❌ 编码实现：工具链混乱，质量参差
- ❌ 代码审查：浅层检查，安全遗漏

### 2. Claude Skill的三大优势
- ✅ 原子化能力封装
- ✅ 可组合的标准化流程
- ✅ 明确的人机协作控制点

### 3. 三个核心Skill的分工
| Skill | 阶段 | 价值 |
|-------|------|------|
| ask-questions | 需求 | 主动提问，精准理解 |
| modern-python | 开发 | 自动化工具链，强制规范 |
| audit-context | 审查 | 深度分析，全面发现 |

### 4. 人机协作的黄金法则
```
Human: 战略决策 + 质量把关
AI + Skill: 标准化执行 + 知识应用
```

### 5. 选Skill的三步法
1. **识别痛点** → 明确需要什么能力
2. **查找Skill** → 在市场中匹配
3. **验证特征** → 确认可控、可测、可理解
